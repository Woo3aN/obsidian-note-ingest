# 录音稿 / 字幕稿

> 本文是 `SKILL.md` §4「其他材料类型」的录音稿部分展开。**何时读**：材料是录音转写稿、网课 / 视频字幕稿时。

特点：没有标点、口语化、大量与知识无关的串场话。

## 先原样提取，别经过上层文档工具

录音稿是 `.docx` 时，直接走 `extract.py`：

```bash
$PY $S/extract.py "<录音稿.docx>" --stats --out "<临时文件>"
```

有些 Agent 框架会把本地 docx 的内容工作路由给一个「文档编辑」工具，而这类工具**读接口常对单段长度
设上限**（例如每段只返回 200 字符预览）。长录音稿单段可达上千字，**读长文档等于读残**。
`extract.py` 直接走 python-docx，段落的文字是完整的。

**动手前先核对量级**：确认拿到的段数和总字数与你预期相符（`--stats` 会给）。
若正文明显短于预期，说明中间有环节截断了，回查工具链而不是硬着头皮往下做。

## 怎么用

- 脚本已按停顿自动分段（阈值自动推断——固定 5 秒一屏的字幕稿会被识别为更长阈值，不会被切碎）。
- **标点和书面化表达必须自己补**，这是字幕稿变笔记最关键的一步。
- 老师口述的例子、类比、踩坑经验往往比课件上的结论更有价值，不要一看是口语就删。
  **但「老师的话」≠「该进笔记的话」**，两种口述的分界线：
- **默认删**：人物轶事、奖项、年代背景、机构典故、对未解之谜的畅想、老师的自我感想
  （自述难度、劝退、鼓励）——一句考点都没有，只会稀释笔记。
- **默认留**：判断方法、直观解释、易错提醒；指针型信息（仪器名、「下一章会讲」）压成半句留。
- **尺子（都要过）**：删掉它会丢知识点 / 易错点 / 方法 / 记忆钩子吗？它是帮解题 / 帮理解，
  还是帮还原课堂气氛？
- **落笔时就把关，别指望写完再精简**——混进正文再挑，成本高还容易漏。
- **口述内容要融进对应知识点，不要单列一个小节。** 把录音稿单独整理成
  `### 课堂实录要点（§X 录音补充）` 堆在章节末尾是错误做法——应当按知识点拆分，
  逐条插到对应小节里（用「下一节的标题」当锚点，把内容插到它**前面**，等于追加到上一节末尾；
  全部插完再删掉那个中间小节）。插入时同样守色块上限——口述内容**优先写成正文 / 列表**。
- **录音稿和课件是互补的，两份都要用**：课件给结构和公式，录音稿给「为什么这么讲」。
  老师反复强调的判断（某个判据有哪几条、某个概念为什么更难理解、某个约定只是习惯不是结论、
  某个方法适用范围窄不要求掌握）往往只在录音稿里，正是笔记最值钱的部分。落笔前把两份都通读一遍。
- **两份冲突时一律以课件为准**——老师口语里数字和方向容易记错，课件是印好的。
  录音稿里可能出现的错误：数值与权威取值差一个数量级、方向说反（说「变强了」而公式显示被削弱）。
  **别照抄录音稿的数值和方向**，逐条拿课件对一遍，对上的才写，
  写错的地方在汇报里说明是哪一处、按什么改的。
- 录音稿里老师的**个人偏好**（如「算某个量时我习惯直接带符号、正负用文字说明」）不是知识点，
  但值得用一两句话记下来——考试按另一种写法也不会错，别让人以为只有一种做法。
- **机器转写的稿子质量可能很差**（同音字、整句不可解）——这种稿子**只能当线索用**，
  每个公式、每个数值都必须回课件核对；课件里没有的内容（纯口述的判断）才按录音稿写，
  写之前用常识过一遍，转写错误的词按上下文还原后在汇报里说明。
