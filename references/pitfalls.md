# 故障排查

> 本文是 `SKILL.md` §5 的展开。**何时读**：写入报错、笔记被改坏了、lint 报了看不懂的行号时。

## 写入相关

- **`check` 的退出码 10/11 不是故障**，是判定结果，按结论走（注意覆盖率虚高的例外，见 `SKILL.md` §3.4）。
- **笔记里已有同名标题时 `insert` 会警告锚点冲突**——别硬插，改成合并进已有章节。
- **插入前用 `outline` 确认锚点标题逐字一致**（含全角括号、中英文混排），写错就定位不到。
- **备份按内容去重**：内容与**最近一份**备份完全相同时，`vaultio` 跳过不存，日志打
  「内容与上一份备份相同，未新增」。所以**别拿时间戳当「改前版本」的凭证**——
  要确认某份备份装的是不是你要的那版，按行数 / 关键词计数核一下。
  （备份目录在 vault 里，vault 又常在同步盘上，会越堆越多：`backups --prune --keep 10` 清理。）
- **改坏了先别慌，`vaultio` 每次写入都自动备份**：`backups` 列时间戳 → `restore --stamp`
  一键回滚，几十行的误删能在一分钟内恢复干净。

- **批量改动一次做完：`vaultio.py patch`**（别拆成十几次 `replace`）：

  ```bash
  $PY $S/vaultio.py patch "<笔记>" --edits-file edits.txt --dry-run   # 先预览
  $PY $S/vaultio.py patch "<笔记>" --edits-file edits.txt             # 落盘
  ```

  `edits.txt` 里每处改动用三行隔开（多行内容不用转义），想「追加」就把原文一起写进新块：

  ```
  <<<<<<< OLD
  （笔记里现有的原文 —— **子串级匹配**：可以只取某个长行的一段，跨行时整段照抄；
   要求逐字符一致、且全文只出现一次）
  =======
  （换成什么）
  >>>>>>> NEW
  ```

  **任一原文没有唯一命中 → 整批不落盘**，并逐条报出命中次数。一次落盘 = 一次备份、
  一次 diff、只问用户一遍。改完看 diff 的 `<` 行：**该删的应该只有你写进 OLD 的那几条**。

  0 命中时脚本会带提示，按提示修即可（2026-10-09 实测）：
  - **行内片段**：锚点取的是长行的后半段、却带着行首 `> ` / `- ` 前缀 —— 去掉前缀按片段写；
  - **最像的行**：整行相似度 ≥0.6 的候选 —— 多半是手抄时差了字。
  边界：OLD / NEW 内容里**单独成行的 `=======`** 会截断解析（fail-fast、只报错不写错），
  真有这种行就换一种分隔写法（如 `=========`）。

- **`toc` 只按笔记现有的排版重建。** 默认沿用现有目录的样子（分组式 / 平表式）；
  认不出（比如手写的 `- [[#…]]` 列表）就**拒绝重建、一个字节都不动**，
  让用户手工维护；真要换排版得显式给 `--group-by 0|1|2`。
  **动手前先 `--dry-run`**：机械重建会把你手工排除过的板块（参考资料、本章小结）也带进来，
  用 `--exclude 正则` 去掉。曾经它会静默把「### 第 N 章 …」的组标题拉平成普通条目、编号全乱。

## 行尾与文件编码

- **写 vault 文件一律走 `vaultio.py`，别手工用 Python 写。** 脚本内部已强制 `newline="\n"`；
  手工 `open(p, "w")` 在 Windows 上会按 `\r\n` 落盘，把**整个文件**的行尾改掉——
  `diff` 会显示全文重写，用户会以为你动了他所有内容。万一写坏了：
  ```bash
  $PY -c "
  p = r'<笔记>'
  raw = open(p, encoding='utf-8', newline='').read()
  open(p, 'w', encoding='utf-8', newline='\n').write(raw.replace('\r\n', '\n'))
  "
  ```
- 库内笔记行尾统一是 **LF**；`vaultio` 读入时会顺手把 CRLF 归一成 LF，这是预期行为。
- **改完一定要 diff 备份核对**：`diff "<vault>/.obsidian-note-backups/<stamp>/<相对路径>" "<笔记>"`。
  正常情况下 diff 只该显示你改的那几行；若显示「整个文件都变了」，第一嫌疑就是行尾符。
  顺便数一下 diff 里的 `<` 行数给用户看，最省事地证明「只删了该删的」。
- **库内笔记本来就有若干**行尾双空格（Markdown 硬换行语法），lint 会报「行尾多余空格」建议
  ——这是**原有写法**，别去「修」它，改前先和备份比一下数量。
- **绝不对素材做 NFKC 归一化**，它会把中文全角标点（，：；）转成半角。`extract.py` 已规避，别在别处引入。

## 不要用 shell 重定向写文件

🚨 **`cat >> 文件 << 'EOF'` 在某些环境的 shell 里不是追加，而是从头覆盖**——
结果是「新内容 + 旧文件尾部字节」拼在一起，接缝处的多字节字符被拦腰截断
（表现为 `SyntaxError: unterminated string literal` 或原有行被吞掉）。
**凡是往已有文件写内容，一律：**

1. 只想改一小段 → 用**文本编辑能力**（局部替换）；
2. 要重写整篇 / 追加一大段 → **先完整读一遍，再整体覆盖写入**（把新旧内容一起写进去）；
3. 非要用脚本 → Python 用 `newline="\n"` 写入，写完立刻自检 `\uFFFD` 是否出现。

🚨 **某些环境的 shell 会把内容里的 `csc` 当 C# 编译器拦截**，也会让 heredoc 触发别的误判——
结论同上：写文件不要走 shell 重定向。含 `\csc` 的整理稿改用文件写入能力写出 `.py` 脚本或内容文件再执行。

## 围栏与结构

- **在代码块附近插内容时，围栏数要数清。** 替换时若自己补了一个围栏、而原文那一处本来就有，
  就会多出一个孤立围栏、全篇围栏变**奇数**。症状：lint 报「代码围栏未闭合」，
  **但报的行号是文件末尾最后那个围栏，真凶在前面几百行**——
  别顺着报错行号找，先数全篇围栏奇偶，再列围栏行号，定位「开了没闭」的那一处。
- **图 + 图注不要套 `| | |` 表格**（表头 2 列、图注行 1 列，lint 会报列数不一致）。直接写三行：
  ```markdown
  ![图 3.4 某过程的示意](imgs/ch3-3.4-某过程示意.png)

  *图 3.4　某过程的示意（课件）——图中标注说明各量的含义*
  ```
  **别用正则批量匹配图注**——图注里常出现 `A\*` 这类转义（`\*` 会截断 `[^*]*`）和含特殊字符的公式。
  改用**逐行状态机**（识别「空表头行 + 分隔行 + 图片行 + 图注行」四行一组），顺手剥掉单元格首尾的竖线。
- **表格单元格里的公式别写 `|`**（2026-10-09 踩）：`$\big|y-f(x)\big|$`、`$P(y|x)$`、`$P(D\|\theta)$`
  里的 `|` 会被 lint 当成**列分隔符**，报「表格列数不一致：本表出现 [3, 5] 列」。
  改用 `\lvert … \rvert`（绝对值）与 `\mid`（条件 / 给定竖线）：`$\lvert y-f(x)\rvert$`、`$P(y \mid x)$`。
  注意 `\|` 在 KaTeX 里是双竖线 `‖`、不是「给定」，也不是安全的转义写法。
  **表格外**的公式不受影响，照常写 `|`。改完必须再跑一次 lint——这类问题**源码里看不出来**。

## 其他

- **用户说「继续」却没说新材料在哪时，按修改时间列一遍下载目录**：课件与录音稿往往
  同一晚一起下载。**别用 `find -newermt`（Windows 没有）**，用跨平台的一行（只读，不写文件）：

  ```bash
  $PY -c "import pathlib,time;d=pathlib.Path.home()/'Downloads';ps=sorted(d.iterdir(),key=lambda p:-p.stat().st_mtime);[print(time.strftime('%m-%d %H:%M',time.localtime(p.stat().st_mtime)),p.name) for p in ps[:15]]"
  ```

  把候选列给用户确认，比反问「材料在哪」快。
- **材料只讲到一部分时**（如「就整理到录音截止的地方」）：只写已讲内容，未讲授部分在文末列一个
  `[!todo] 待上课整理` callout（保留课件原小节号和一句内容提要）；范围 callout 里注明「课堂只讲到此」；
  **只讲了前半时未用到的图直接从 `imgs/` 删掉**，不留孤儿图。
- **多份 PDF 渲染到同一个 `--out` 目录会互相覆盖**：`renderpages.py` 输出文件名只有 `pNNN.png`，
  两份材料都有第 1 页，后渲染的覆盖前者。**每份材料用独立子目录**：`--out "$T/imgs/ch1"`。
- **练习题题面括号必须渲染原页核验。** 课件 PDF 的 OCR 会丢括号，而公式一丢括号就产生
  「左结合 vs 右结合」的歧义，**答案完全不同**。**凡题面涉及运算符混排、或含多层括号，一律渲染该页看图确认**；
  课件没写括号就照官方题面抄，别自己补。
- **拿到带答案的材料时，回头核对已写进笔记的自算答案。** 上一轮「课件无答案 → 整理时自算」的解答，
  下一轮材料里可能就有官方版了。核完把标注从「整理时自做」改成「已与官方答案版核对」，
  并**明确告诉用户哪几题原本算错了**——这正是用户最在意的部分。
- **同一份材料出了新版（答案版 / 修订版）时**：先 `pdfdiff.py 旧.pdf 新.pdf` 定位到改动过的那几页，
  只渲染那几页看图核对，别通读两份。命中率高的话 `check` 会给退出码 13
  （= 版本修订），按「逐处替换」处理，而不是当重复内容丢掉。
- 脚本里裁图保存用 `PIL.Image.fromarray(crop).save(p)`；别用 `fitz.Pixmap(csRGB, IRect, bytes)`
  直接构造，新版 pymupdf 会报 `Unrecognised args`。
- **callout 被空行截断的自检**（用 `replace` 写 callout 时最该看的）：`vaultio replace` 会自己处理——
  它先判断前缀末行与后缀首行是否都以 `>` 开头，若是（说明替换发生在引用块内部）就**不补**那个分隔空行，
  并打印 `[提示] 替换发生在引用块内部，已省略分隔空行`；替换完成后还会扫全文，
  发现别处被截断就用 `[警告]` 报出行号。**看到 `[提示]` 是正常处理，看到 `[警告]` 就去看那一行。**
  兜底自检（任何时候可跑）：**空行前后两行都以 `>` 开头、且后一行不是 `> [!`** —— 就是被截断，
  删掉那个空行即可。
  **最省事的预防：一次性 replace 整个 callout（`--until` 伸到它最后一行），别做局部行替换。**
- vault 路径含中文和空格，命令里一律用双引号包住。
